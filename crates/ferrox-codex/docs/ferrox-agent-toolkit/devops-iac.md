# 🚀 Production DevOps & Infrastructure-as-Code (IaC)

The **Ferrox Agent Toolkit** automates production-grade containerization and cloud infrastructure provisioning through `ferrox-devops-architect` and `rules/ferrox-devops-infrastructure-iac.md`.

Deployments adhere to the principle of minimal attack surface, rapid boot times ($< 50\text{ms}$), and declarative infrastructure reproducibility.

---

## 🐳 Ultra-Light Distroless Docker Images ($< 25\text{MB}$)

Every backend microservice generates a multi-stage `Dockerfile` utilizing Google Distroless base images (`gcr.io/distroless/cc-debian12` or `static-debian12`).

```dockerfile
# Multi-stage distroless Rust build example
FROM rust:1.80-bullseye as builder
WORKDIR /app
COPY . .
RUN cargo build --release --bin server

FROM gcr.io/distroless/cc-debian12
COPY --from=builder /app/target/release/server /usr/local/bin/server
USER nonroot:nonroot
EXPOSE 8080
ENTRYPOINT ["/usr/local/bin/server"]
```

### Key Security Benefits:
- **No Package Manager**: `apt`, `yum`, or `apk` are absent, preventing attackers from downloading malicious binaries.
- **No Shell**: No `/bin/sh` or `/bin/bash` available, neutralizing arbitrary command execution exploits.
- **Non-Root Execution**: Runs as unprivileged user `nonroot` ($UID\ 65532$).
- **Instant Pulls**: Typical image sizes range from $12\text{MB}$ to $22\text{MB}$.

## ⚡ Redpanda & Redis Local Orchestration (`docker-compose.yml`)

The toolkit provisions local developer environments mirroring production distributed topologies:

```yaml
version: "3.8"
services:
  redpanda:
    image: docker.redpanda.com/redpandadata/redpanda:v24.1.1
    container_name: ferrox-redpanda
    ports:
      - "9092:9092"
      - "9644:9644"
    command:
      - redpanda start
      - --smp 1
      - --memory 512M
      - --overprovisioned
      - --kafka-addr PLAINTEXT://0.0.0.0:9092

  redis:
    image: redis:7.2-alpine
    container_name: ferrox-redis
    ports:
      - "6379:6379"
    command: ["redis-server", "--appendonly", "yes", "--requirepass", "${REDIS_PASSWORD:-ferrox_secret}"]
```

## ☁️ Declarative Terraform Cloud Scaffolding

For cloud deployments (AWS, GCP, Hetzner, or DigitalOcean), the toolkit generates modular Terraform manifests:

```hcl
# Example Terraform manifest generated by ferrox-devops-architect
module "ferrox_service" {
  source       = "./modules/vps_container"
  service_name = "checkout-saga-service"
  image        = "ghcr.io/ai-autistic-intelligence/checkout-saga:latest"
  memory_limit = "512M"
  cpu_quota    = "1.0"
  environment = {
    PORT            = "8080"
    REDPANDA_BROKERS = "redpanda:9092"
    REDIS_HOST      = "redis:6379"
  }
}
```
